# Практическое задание. Имена полей настроек

**Цель**

Создать декларативный макрос для описания структуры и процедурный `derive`-макрос для чтения её полей.

**Задание**

1. Создать рабочее пространство Cargo из пакета `settings` и отдельной библиотеки `field_names_derive`. В манифесте библиотеки указать `proc-macro = true` в секции `[lib]`. В `settings` подключить библиотеку как зависимость по пути.
2. В `field_names_derive` реализовать `#[derive(FieldNames)]` для необобщённых структур с именованными полями. Макрос добавляет ассоциированную функцию `field_names() -> &'static [&'static str]`, которая возвращает имена полей в порядке объявления.
3. В `settings` написать `macro_rules! settings`. Вызов `settings! { Config { host: String, port: u16 } }` создаёт структуру `Config` и применяет к ней `#[derive(FieldNames)]`.
4. Написать тесты для `Config` и второй структуры с другим набором полей. Проверить применение `FieldNames` напрямую на второй структуре.

**Подсказки по ключевым частям**

- В `macro_rules!` использовать `ident` для имён, `ty` для типов и повторение для списка полей.
- Процедурный макрос получает `TokenStream`. Для разбора объявления и генерации `impl` подойдут `syn` и `quote`. Строки с именами формируются при компиляции.

**Что проверить перед отправкой**

- [ ] `cargo test --workspace` проходит. `Config::field_names()` возвращает `["host", "port"]`.
- [ ] Для второй структуры возвращаются её собственные имена в порядке объявления.
- [ ] Перечисления и структуры с безымянными полями приводят к понятной ошибке компиляции. Имена полей берутся из объявления структуры.

**Советы по улучшению работы**

Поддержать необязательную запятую после последнего поля и добавить документационный тест `compile_fail` для неподдерживаемой формы.
