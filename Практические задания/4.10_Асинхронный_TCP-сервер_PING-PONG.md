# Практическое задание. Асинхронный TCP-сервер PING/PONG

**Цель**

Обслуживать несколько TCP-соединений на одном потоке среды выполнения, ограничивать число активных обработчиков и освобождать ресурсы по таймауту.

**Задание**

1. Запустить `tokio::net::TcpListener` на локальном адресе с однопоточной средой выполнения Tokio. В цикле принимать соединения и запускать для каждого клиента отдельную асинхронную задачу.
2. Читать одну строку с окончанием `\n`. На `PING\n` отправлять `PONG\n`, на любую другую полную строку — `ERR\n`. После ответа закрывать соединение.
3. Ограничить чтение двумя секундами. При истечении времени, закрытии клиентом соединения до конца строки или ошибке чтения завершать обработчик.
4. Ограничить число активных обработчиков семафором. При исчерпании разрешений ждать освобождения места перед следующим `accept`. Задать лимит `64` для обычного запуска и предусмотреть меньший лимит для тестов.
5. Проверить параллельное обслуживание. Оставить первое соединение без данных, а по второму отправить `PING\n` и получить ответ до таймаута первого.

**Подсказки по ключевым частям**

- `TcpListener::accept` и чтение из сокета при ожидании отдают управление другим задачам. Для чтения использовать `tokio::time::timeout` вокруг асинхронной операции.
- Переместить разрешение семафора в обработчик. При выходе из задачи оно освобождается вместе с её локальными значениями.
- Для тестов привязать слушатель к `127.0.0.1:0` и получить фактический адрес через `local_addr()`.

**Что проверить перед отправкой**

- [ ] `PING\n` и неверная команда получают ожидаемые ответы. Соединение закрывается после ответа.
- [ ] Молчащий клиент и клиент с неполной строкой не задерживают другие запросы при наличии свободного места. По таймауту слот освобождается.
- [ ] При лимите в два обработчика третий клиент получает ответ после освобождения слота. Ошибка отдельного клиента не останавливает сервер.

**Советы по улучшению работы**

Ограничить длину входной строки. Начать нагрузочную проверку со 100 клиентов и постепенно увеличивать число соединений до 10 000. На каждом шаге фиксировать число успешных ответов, ошибок и время обработки.
