# Практическое задание. Общий интерфейс очереди и дека

**Цель**

Выразить общий контракт через обобщённый трейт, расширить его новым трейтом и повторно использовать реализацию через композицию.

**Задание**

1. Описать трейт `Queue<T>` с операциями `enqueue`, `dequeue` и `len`. Для `dequeue` использовать `Option<T>`, а `is_empty` реализовать в трейте через `len`.
2. Описать трейт `Deque<T>: Queue<T>`. Добавить операции `push_front` и `pop_back` для второго конца очереди.
3. Реализовать `Queue<T>` для структуры `Fifo<T>` с закрытым полем `VecDeque<T>`. Для `VecDeque<T>` реализовать оба трейта, делегируя операции методам коллекции.
4. Написать функцию `take_first<T, Q: Queue<T>>(queue: &mut Q, limit: usize) -> Vec<T>`. Она извлекает до `limit` элементов в порядке очереди. Проверить её с обеими реализациями.

**Подсказки по ключевым частям**

- Для обычной очереди вставка происходит в конец, а извлечение — из начала.
- Ограничение `Q: Queue<T>` позволяет одной функции работать с любой реализацией контракта.

**Что проверить перед отправкой**

- [ ] `is_empty` использует реализацию по умолчанию. Пустая очередь возвращает `None`.
- [ ] После добавления `1`, `2` и вставки `0` в начало дека извлечение с конца даёт `2`, а с начала — `0`.
- [ ] `take_first` работает с числами и значениями `String`. При лимите `0` очередь остаётся прежней, при лимите больше размера функция возвращает все элементы.

**Советы по улучшению работы**

Вынести проверки общего контракта в обобщённую тестовую функцию и запустить её для обеих реализаций.
