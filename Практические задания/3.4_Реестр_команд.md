# Практическое задание. Реестр команд

**Цель**

Выбирать реализацию команды во время выполнения через `dyn Trait` и извлекать значение нужного типа через `dyn Any`.

**Задание**

1. Описать трейт `Command` с методом `run(&self, input: &dyn Any) -> Result<String, CommandError>`.
2. Реализовать две команды. `length` принимает `String` и возвращает число символов строкой. `double` принимает `i64` и возвращает удвоенное число строкой.
3. Зарегистрировать обе команды в `HashMap<String, Box<dyn Command>>`. Реализовать вызов по имени. Повторная регистрация имени заменяет прежнюю команду.
4. Различать в `CommandError` неизвестное имя, неверный тип входа и переполнение.

**Подсказки по ключевым частям**

- Внутри команды `downcast_ref::<T>()` возвращает `Option<&T>`. Для умножения использовать `checked_mul`.
- Диспетчер ищет команду по имени и вызывает метод через объект трейта. Проверка типа входа остаётся внутри выбранной команды.

**Что проверить перед отправкой**

- [ ] `length` для `String::from("привет")` возвращает `"6"`, а `double` для `21_i64` возвращает `"42"`.
- [ ] Неизвестное имя, передача строки в `double` и удвоение `i64::MAX` дают разные ошибки без паники.
- [ ] Две реализации хранятся в одном реестре. Повторная регистрация меняет поведение только команды с тем же именем.

**Советы по улучшению работы**

Добавить команду для третьего типа входа, используя существующий интерфейс реестра. Сохранить проверку типов внутри обработчиков.
