# Практическое задание. Статистика показаний

**Цель**

Организовать пакет Cargo с библиотекой и исполняемым файлом. Отделить публичный интерфейс от внутренней реализации.

**Задание**

1. Создать отдельный пакет `readings` с `src/lib.rs` и `src/main.rs`.
2. В `src/parse.rs` реализовать преобразование аргументов в числа `i32`, а в `src/stats.rs` — подсчёт количества, минимума и максимума. Из `src/lib.rs` открыть функцию `summarize(&[String]) -> Result<Summary, SummaryError>` и типы, нужные для работы с ней.
3. В `main.rs` получить аргументы командной строки и вызвать функцию из библиотеки. Команда `cargo run -- 8 -2 5` должна выводить `count=3 min=-2 max=8`. При пустом списке или неверном числе вывести сообщение в стандартный поток ошибок и завершиться с ненулевым кодом.
4. В `tests/summary.rs` написать интеграционные тесты для публичного интерфейса. Проверить обычный набор, одно число, пустой список и неверный аргумент.

**Подсказки по ключевым частям**

- Объявить `mod parse;` и `mod stats;` в `lib.rs`. Для доступа из родительского модуля достаточно `pub(super)` у внутренних функций.
- `main.rs` и интеграционный тест обращаются к библиотеке через имя пакета `readings`.

**Что проверить перед отправкой**

- [ ] `cargo check --all-targets`, `cargo test` и `cargo build` проходят из корня пакета.
- [ ] Пример запуска даёт ожидаемые числа. Пустой ввод и `cargo run -- 8 x` завершаются с ошибкой без паники.
- [ ] Интеграционные тесты используют публичный интерфейс. Модули разбора и расчёта закрыты для внешнего кода.

**Советы по улучшению работы**

Указать неверный аргумент в сообщении об ошибке и описать формат запуска в README пакета.
